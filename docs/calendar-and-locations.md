## Working calendar methods

- Manual: name, section, start/end, weekly days, building/code, room, optional date range/notes. Add/edit/delete, duplicate detection, overlap warnings, local IndexedDB persistence, explicit clear/replacement confirmation. Editing manual recurrences changes the series; imported expanded occurrences are edited individually.
- ICS: browser-local `ical.js` parser. Google/Outlook/Apple exports; VEVENT, RRULE, EXDATE, date-time RDATE, recurrence exceptions/cancellations, UTC/IANA/embedded VTIMEZONE, DST and all-day events. Floating times explicitly use Los Angeles. Unknown zones/times are skipped with warnings, never guessed. Limit: 2 MB, 500 definitions, 120-day import window, 10,000 expansion iterations and 2,000 saved occurrences. High-frequency rules and period-valued RDATE are not supported. Re-import for future occurrences; existing identical entries are skipped. Stable source occurrence IDs intentionally avoid duplicate imports; delete old corrected occurrences or use confirmed replacement when the provider export changes them.
- Review imports before saving. Categories default **unclassified**; the user must mark actual classes. All-day events cannot drive gap routing. Titles/buildings/categories can be corrected in preview; times and other details via Edit after saving, before requesting any recommendations. Overlapping class times block gap planning.
- Weekly calendar: Monday–Sunday, dated blocks, today, next class in the viewed week, selectable day, agenda/edit/delete, gap projections and backups. Los Angeles wall times retain weekly schedules across DST; ambiguous/nonexistent manual times require correction.
- Screenshot: lazy local Tesseract OCR; PNG/JPEG/WebP up to 5 MB and 16 megapixels. Image stays on device. First use downloads worker/language assets from the library's CDNs and needs connectivity. Grid OCR is not reliably structured; raw text is editable. Conservative row format: `Title | Mon,Wed | 09:00-10:15 | LVL | 201`. Missing fields are not invented; manual entry is the complete fallback. Review and mark classes before saving. Actual screenshot accuracy varies and is not guaranteed.
- Apple Calendar on macOS: select a calendar → File → Export → Export, then upload `.ics`. No Apple account/password or direct synchronization.

## Shared engine, privacy and MCP

The website sends only selected-day class locations/start/end to existing `/api/plan-day`, not titles, notes, screenshots or complete calendars. No backend calendar database, user account or schedule logging was added. Responses add `reset_request` and `recommendations` while retaining the previous first `recommendation` field. This preserves both walking legs, cutoff, next-class deadline, backup/swap and conservative eligibility rules. Planned future gaps are **projections**, not current conditions. Opening a live break keeps its deadline and uses the remaining time; extending a long gap is not allowed to reset a swap budget.

The original four MCP tools remain. `plan_day` accepts its existing `classes` list or a new `events` list of already expanded, reviewed occurrences (`id`, `source`, `title` optional/blank, `start`, `end`, `time_zone`, `recurrence`, `location`, `building_code`, `category`, `source_event_id`). Do not send both. Only events explicitly categorized `class` are used. Timezone-aware times, valid IANA zone and nonoverlap are required; at most 20 classes. MCP cannot read browser-local IndexedDB. Prefer omitting private titles/notes.

Schedule and provider tokens are never put in shareable links. Clear local schedule deletes IndexedDB records and current import/OCR preview; disconnect clears temporary provider credentials. Demo schedules remain separate and are not persisted as actual student records. Device accessibility preferences remain under their existing separate controls.

## Microsoft read-only OAuth (registration needed)

The browser implementation is present but **no live account authentication is claimed or tested without credentials**. Official references: [authorization code + PKCE](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow), [calendar view](https://learn.microsoft.com/en-us/graph/api/calendar-list-calendarview?view=graph-rest-1.0).

1. In Microsoft Entra admin center → App registrations → New registration. Choose supported accounts (including personal accounts if needed).
2. Authentication → Add platform → **Single-page application**. Add exact redirect URLs `https://neuro-route-nine.vercel.app/oauth-callback.html` and local `http://127.0.0.1:5173/oauth-callback.html` for testing. Preview domains need their own exact registered URI. Do not enable legacy implicit grant or add a client secret.
3. API permissions → Microsoft Graph → Delegated permissions → **Calendars.ReadBasic** only. Tenant administrators may need to allow user consent. This application does not write calendars or request offline access/refresh tokens.
4. In Vercel set `VITE_MICROSOFT_CLIENT_ID=<public application UUID>` and `VITE_MICROSOFT_TENANT_ID=common` (or the registered tenant UUID). Redeploy; these are public build-time identifiers, never secrets.
5. My Schedule → Connect a read-only calendar → Connect Microsoft Outlook. Consent popup uses random state, PKCE S256, exact origin/source message validation, one-time code, three-minute timeout. Tokens/verifier remain in memory; token exchange uses POST, not URL tokens. OAuth callback removes the code query immediately. Select a calendar, select up to 120 days, explicitly Import/refresh, review categories/buildings, then save. At most 400 events/four pages. Larger imports fail without saving partial results.
6. Disconnect removes app session credentials; remove consent separately in the Microsoft account if desired. Clear local schedule separately to delete imported records. Reload/navigation away also ends the temporary session. No background syncing.

## Google read-only connection (registration needed)

The Google Identity Services browser **token model** is implemented, but **live account consent has not been verified without an owner OAuth client**. It uses the official GIS popup transport, explicit consent, a checked random state, temporary memory-only access token, and no client secret or refresh token. No authorization-code exchange occurs, so PKCE is not applicable to this GIS token flow. The Microsoft code flow separately uses PKCE. References: [GIS token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model), [GIS JavaScript reference](https://developers.google.com/identity/oauth2/web/reference/js-reference).

1. Google Cloud Console → APIs & Services → enable **Google Calendar API**. Configure OAuth consent screen with app name, support email, privacy policy, test users and scope `https://www.googleapis.com/auth/calendar.events.readonly` only.
2. Credentials → Create OAuth client ID → **Web application**. Add authorized JavaScript origins `https://neuro-route-nine.vercel.app` and local `http://127.0.0.1:5173`; add exact preview origins only if testing them. This popup token flow does not use a backend redirect callback or client secret.
3. Set Vercel `VITE_GOOGLE_CLIENT_ID=<public web client ID ending in .apps.googleusercontent.com>` and redeploy. Never put a client secret into `VITE_*` or this repository. Credentials must belong to the owner; none are invented here. Google test-user/verification restrictions may apply.
4. My Schedule → Connect a read-only calendar → Connect Google Calendar. GIS is loaded only on this explicit action. Consent grants read-only events on the **primary calendar only**; calendar selection is not implemented and no calendar-list scope is requested. If the popup is blocked after SDK loading, retry or use ICS.
5. Select the import range (up to 120 days), Import/refresh Google primary calendar, review each event's category/building, then save. Recurring events are expanded by Google `singleEvents=true`; at most 400 occurrences/four pages. Larger imports fail without saving partial data. Calendar event bodies are not requested.
6. Disconnect clears the in-memory session, and Revoke Google consent additionally requests provider revocation. Reload/navigation away clears tokens. Saved local imports must be deleted with Clear schedule. No background sync, insecure refresh-token storage, token URLs, new database or paid service.
