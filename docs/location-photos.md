# Location photos

These images are bundled locally so the cards do not depend on external image servers. They are real location/building photographs, not generated images or live views. Google/web image search was used for discovery; Wikimedia Commons file pages and license metadata were checked before downloading. An exterior is labeled as an exterior, never passed off as the exact room or seating area. Photos do not establish opening hours, crowd levels, seating, or accessibility.

To add more, place an authorized image in `frontend/public/locations`, add its attribution to `frontend/src/data/location-photos.json`, and explicitly assign a spot ID or building code. Keep the exact-room versus building distinction honest. Existing scout-import `photo_url` values still take precedence; only public HTTPS image URLs are rendered. Maintain source/permission information for team-supplied images.

## UX

Directory cards show a photo, name, one location line, any reservation requirement, and one walking action. Amenity unknowns, sources, credits and routing caveats are behind a native **More info** disclosure. Reset cards retain walking/rest/leave-by times and full/backup actions, with explanations and unknown crowd details also under More info. Images load lazily, have text alternatives and fixed dimensions, and degrade to a stable placeholder on errors.

No API, route scoring, calendar, scouting data, deployment variables or dependency changes. Use the existing Vercel deployment; the backend does not need an update for this frontend-only change.
